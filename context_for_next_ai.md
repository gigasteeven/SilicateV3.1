# Контекст проекта "Trakines" для продолжения разработки (Geode Mod для Geometry Dash)

## Суть проекта
**Trakines** — это мод для Geometry Dash 2.2081, разрабатываемый на базе фреймворка **Geode SDK 5.7.1**.
Мод предоставляет функционал двойного рендеринга (dual-render pipeline):
1. **Игрок** видит геймплей в **Layout Mode** (синий фон, белые силуэты платформ, весь декор скрыт).
2. **OBS (или любая другая программа)** получает через **Spout2** полный кадр со всеми декорациями и оригинальными цветами.
3. В **меню, на паузе и в редакторе** мод неактивен, и через Spout2 передается точная копия (1:1) экрана игры.

Таким образом, игрок может комфортно играть без отвлекающего декора, а зрители на стриме видят красивую полную версию уровня.

## Текущий прогресс и что уже сделано
Проект частично инициализирован. Вот список файлов, которые уже созданы и находятся в репозитории:

1. `mod.json` - Манифест мода с нужными настройками (включение мода и Spout).
2. `CMakeLists.txt` - Настроен для загрузки `Spout2` напрямую из GitHub (через `FetchContent`) и сборки нужных `.cpp` файлов SDK вместе с модом, чтобы не было внешних зависимостей.
3. `.github/workflows/build.yml` - CI для автоматической сборки мода под Windows (Spout2 работает только на Windows).
4. `src/global.hpp` - Синглтон `TrakinesGlobal` для хранения состояния:
   - `layoutMode` (включен ли режим).
   - `spoutEnabled` (включен ли Spout).
   - `inPlayLayer` (находимся ли мы в уровне).
   - `renderingForSpout` (критический флаг: `true`, когда мы в данный момент рисуем кадр для отправки в OBS, чтобы хуки Layout-режима пропускали модификацию объектов).
5. `src/layout_mode.hpp` - Содержит все необходимые константы из мода XDBot (списки ID объектов, которые нужно скрыть, список ID триггеров, новые цвета и т.д.).
6. `README.md` и `.gitignore` - Базовая документация и игнор-файл.

Также есть файлы `implementation_plan.md` и `task.md` в рабочей директории с подробной архитектурой.

## Что осталось сделать (Задачи для следующего ИИ)

### 1. Реализовать логику Layout Mode
Нужно создать `src/layout_mode.cpp` (используя константы из `layout_mode.hpp`). Логика основана на исходниках XDBot:
- Хук `LevelTools::verifyLevelIntegrity`, чтобы игра не ругалась на измененный уровень.
- Логика модификации `levelString` перед загрузкой уровня (чтобы изменить фон и базовые цвета на синий/белый).
- Самое важное: Хук на добавление объектов (обычно `PlayLayer::addObject`). Если объект — это декор (ID есть в `decoObjectIDs`), его нужно скрыть. Если это структура — перекрасить в белый.
- **ВАЖНО:** Эта логика должна применяться **ТОЛЬКО** если `TrakinesGlobal::get().renderingForSpout == false`. Если флаг `true`, мы рендерим оригинальный уровень для OBS, и хук не должен модифицировать объекты.

### 2. Реализовать Spout2 Wrapper
Нужно создать `src/spout/spout_sender.hpp` и `src/spout/spout_sender.cpp`.
- Класс-обертка для `SpoutSender`.
- Метод инициализации с именем `Trakines` и размером окна `CCDirector::sharedDirector()->getWinSizeInPixels()`.
- Метод отправки OpenGL текстуры: `spoutSender.SendTexture(textureID, GL_TEXTURE_2D, width, height, true, 0);`

### 3. Реализовать пайплайн двойного рендеринга (Main Hooks)
В `src/main.cpp` нужно создать основные хуки на Cocos2d-x и Geode:
- **`PlayLayer::init`** и **`PlayLayer::onQuit`** - для переключения флага `TrakinesGlobal::get().inPlayLayer`.
- **`CCDirector::drawScene`** - здесь происходит главная магия:
  ```cpp
  // Псевдокод для CCDirector::drawScene
  if (global.inPlayLayer && global.layoutMode && global.spoutEnabled) {
      // 1. Устанавливаем флаг, что сейчас рендерим для Spout
      global.renderingForSpout = true;
      
      // 2. Создаем или используем существующий CCRenderTexture размером с экран
      // 3. Вызываем оригинальный drawScene (или заставляем сцену отрисоваться в текстуру). 
      // Т.к. renderingForSpout = true, все объекты отрисуются как в оригинале (с декором).
      
      // 4. Берем textureID из CCRenderTexture и отправляем в Spout2
      spoutSender.sendTexture(textureID, ...);
      
      // 5. Сбрасываем флаг
      global.renderingForSpout = false;
      
      // 6. Вызываем оригинальный drawScene на дефолтный framebuffer. 
      // Теперь объекты будут модифицированы (Layout mode) и игрок увидит синий фон.
  } else if (global.spoutEnabled) {
      // Меню/пауза - просто берем текущий framebuffer (glReadPixels или копируем)
      // и отправляем в Spout2 1:1, затем вызываем оригинальный drawScene
  } else {
      // Обычный рендер
      orig();
  }
  ```
  *(Примечание: подход с `CCRenderTexture` требует осторожного восстановления состояния OpenGL или правильного вызова `visit()` у текущей сцены внутрь текстуры).*

## Основные нюансы и подводные камни
- Для Windows и Cocos2d-x OpenGL контекст должен быть активен при отправке текстуры. Вызов `SendTexture` должен происходить в основном потоке рендера.
- Spout2 использует DirectX/OpenGL interop для zero-copy отправки текстуры, что очень быстро (особенно на RTX 3090 пользователя).
- Не забыть учитывать хоткей (клавиша `U`) для переключения режима на лету (используя биндинги Geode/Cocos).
- Важно не сломать кэширование объектов в Geometry Dash при двойном проходе (если используется). Возможно, вместо двойного `visit()` всего слоя, потребуется использовать шейдеры или скрывать/показывать узлы перед каждым проходом, если двойной вызов `draw`/`visit` ломает логику частиц или триггеров.
